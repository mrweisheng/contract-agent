# UI 页面×区块规约（防串页回归）

> 本文档回答一个问题：**为什么一种页面的东西绝不能出现在另一种页面上，以及我们靠什么保证这件事。**
> 事实源：页面×区块矩阵的可执行版本 = `scripts/test_ui_smoke.mjs` 的 `MATRIX`。本文件的表格是它的人读版，两处必须同改。

## 一、为什么有这份规约（复盘：2026-11-26 结算单页渲染出合同）

发票页提交（d22f017）往右栏预览区插新分支时，把「结算单 `v-if` → 合同 `v-else`」的互斥链拆断了：
合同预览块的 `<template v-else>` 被错挂到**发票底栏**的 `v-if="isInvoice"` 上——Vue 对 v-else 配错兄弟节点**零报错零警告**，编译完全合法。
真值表恰好「发票✓ 合同✓ 只结算单✗」，人工测试盲区正好漏过，结算单页面出现合同正文铺在成品下面、底栏叠两排。

**错误机理**：`v-else` 的语义是「其余全部」。每新增一种页面，「其余」的范围就变一次；共享栏的条件链只要有一处没接牢，新页面就把旧页面的显隐悄悄改掉。

**同类病史（同一类病，不止发过一次）**：
| 事故 | 共享面 | 隐式假设 |
|---|---|---|
| 结算单页渲染合同（本次） | 右栏预览区的条件链 | v-else「其余」= 合同页，插新页后失效 |
| 切业务漏清实收（9362e2c） | `st.paid` 四业务共用 stSetBiz 复位 | 新增切出路径没对照 stDefaults 全量核对 |
| 两地牌赠品填了没反应 | 多行写回键名写死 `promise_other` | 新业务的键没进写回映射 |

**共通原则：凡是 N 个页面/业务共享一块东西（模板区块、状态、复位逻辑、写回映射），
成员清单必须显式可枚举（点名条件/映射表/矩阵），并且每个成员至少有一条断言钉住它。**
三层防线互相兜底：结构让人难写错，测试让错了必变红，文档让红线不随人忘。

## 二、页面×区块矩阵（人读版）

| 页面 | 左栏 | 右栏 | 右栏底栏 | 备注 |
|---|---|---|---|---|
| 合同业务（卖车/过户/新办/高才） | 合同录入栏 `.pane-body` | 合同实时预览（docx） | 生成合同 → | 落地页即卖车 |
| 结算单 | `.st-pane` | 结算单成品（img） | 生成结算单 → | 全不勾续期时右栏为占位 |
| 电子收据 | `.inv-pane` | 發票實時預覽（SVG） | 下載發票 | 进页自动取號；除「備註」外必填，收款人固定 `陳煥明` 不可改 |
| 合同管理 | 全宽卡片列表 | **无右栏** | — | `isFullPage` |
| 用户管理 | 全宽用户列表 | **无右栏** | — | `isFullPage` |

断言细节（每页右栏「只能有、不能有」什么）以 `MATRIX` 为准：右栏标题文案、底栏文案包含/禁止片段、
合同 docx 单元格数、结算单成品图、发票 SVG、左栏渲染的是哪个 pane-body。

## 三、共享区域规约

**规约 1：跨页共享栏的分支一律显式点名，禁裸 `v-else`。**
- 右栏预览区、左栏录入栏、预览头（pv-head）的按钮组——每个分支写明自己属于哪种页面：
  `v-if="isSettlement"` / `v-if="!isSettlement && !isInvoice"`，不允许靠 else 兜「其余页面」。
- 已显式化的两处（勿改回）：右栏合同预览+底栏（78418d1）、左栏合同录入栏（`v-if="!isSettlement && !isInvoice"`，附注释处）。

**规约 2：语义兜底的 else 例外（允许保留，但必须是有意的默认）**
- 结算单内部：`st.biz === '续期'` → 续期编辑器；else → 杂费编辑器（新增业务默认杂费版式=设计意图）。
- 合同录入：`ledgerMode` 台账式 / else 经典式（二态配置，非页面派发）。
- 判别法：else 兜的是**同页内的模式/状态**（低风险）还是**「哪种页面」**（禁）。拿不准就改显式。

**规约 3：新增共享状态时，切页复位进 `selectMenu`，并对照全量清单核对**（教训见 9362e2c）。

## 四、Checklist A：新增页面类型

1. 在 `scripts/test_ui_smoke.mjs` 的 `MATRIX` **加一行**（它有什么、不能有什么，写成断言）。
2. 左右栏新分支用**显式条件点名**（规约 1），不挂裸 else。
3. `isFullPage` 等 computed 若涉及，确认新页归类正确。
4. 切页复位逻辑进 `selectMenu`（规约 3）。
5. `web/index.html` 资源版本号 bump（`app.js?v=` 递增），否则线上缓存不刷新。
6. 跑 `node scripts/test_ui_smoke.mjs` 全绿；截图新页 + 结算单页（最高危页）给用户过目。
7. 提交信息写明动了哪个共享区域。

## 五、Checklist B：修改共享区域（预览栏/录入栏/顶栏/selectMenu/stSync 等跨页代码）

1. 先 `grep -n "v-else" web/app.js` 盘点该区域全部条件配对，想清楚每个 else 现在兜谁、改完兜谁。
2. 改完跑 `node scripts/test_ui_smoke.mjs` 全绿。
3. 动了条件链的提交，除冒烟外把**结算单页**和发票页各截图目检一眼（矩阵断言抓样式/内容错位，截图抓观感）。

## 六、冒烟脚本用法与前提

```bash
node scripts/test_ui_smoke.mjs
```
- 前提：本地服务已起（start.bat，8300）；`agent-browser` CLI 在 PATH（`npm i -g agent-browser`，首次 `agent-browser install`）。
- 行为：逐页点顶栏→轮询采右栏/左栏结构快照→逐格比对 `MATRIX`，20s 内不达标即红；任何一页失败退出码 1。
- 跑发票页会自动取號（未存档占号 30 分钟自动回收），反复跑会滚动消耗编号段，正常。
- 已知特性：agent-browser 冷启动浏览器可能超过一分钟，脚本对单次调用有 150s 硬超时；
  **不要**给等待条件用无超时的 CLI 调用（networkidle 在本应用上可能永不满足，曾静默挂死）。
