# 对外合同查询接口 + 小程序渲染规范

面向小程序等外部系统：查询已生成合同、按服务端返回的内容块（blocks）渲染合同全文、回传客户手写签名。

**分工**：合同正文的组装（固定条款+动态赠品/附加条款）在服务端生成 docx 时已全部完成，接口把成品拆成 `blocks` 内容块原样返回——前端只做「查询 → 照块渲染 → 签名回传」三件事，不需要任何合同模板知识。

## 鉴权

- 服务端配置环境变量 `OPEN_API_KEY`（未配置时整个接口前缀返回 403，即对外关闭）
- 每个请求带 Header：`X-API-Key: <key>`，或 URL 参数 `?key=<key>`
- **可见范围**：只对外提供 **2026-11-22（含当天）及以后生成**的合同。更早的单在列表里不出现，按编号直接查详情/下载/签名一律返回 404（与「不存在」同语义，不提示历史单是否存在）

## 接口

### 1. 查询列表

```
GET /api/open/contracts?client=张&type=car&limit=50
```

返回：

```json
{"total": 1, "items": [{
  "no": "20261118001", "type": "car", "client": "陈大文", "mode": "default",
  "currency": "HKD", "filename": "20261118陈大文卖车.docx",
  "created_at": "2026-11-18 15:30:12", "review_status": "pass",
  "signed": false, "signed_at": ""
}]}
```

`type` 取值：`car` 卖车 / `car_buy` 收车 / `transfer_gx` 高新过户 / `transfer_ns` 纳税过户 / `new_port` 粤Z新办 / `immigration` 高才移民。

### 2. 查询单份（内容块 + 结构化数据）

```
GET /api/open/contracts/{no}
```

返回元数据 + `blocks`（渲染合同全文用这个）+ `content`（补充数据）：

```json
{
  "no": "20261118001", "type": "car", "type_label": "卖车（香港车辆买卖）",
  "client": "陈大文", "signed": false, "signed_at": "",
  "blocks": [
    {"kind": "meta",     "text": "合约编号 / AGREEMENT NO.: 20261118001    签署日期 / DATE: 2026年11月18日"},
    {"kind": "title",    "text": "车辆买卖合约（香港）"},
    {"kind": "subtitle", "text": "MOTOR VEHICLE SALE AND PURCHASE AGREEMENT · HONG KONG"},
    {"kind": "h",        "text": "一、合约双方", "en": "PARTIES"},
    {"kind": "table",    "rows": [["甲方（卖方） SELLER", "华星资源开发有限公司", "乙方（买方） BUYER", "陈大文"], ["…"]]},
    {"kind": "h",        "text": "五、附赠服务", "en": "COMPLIMENTARY SERVICES"},
    {"kind": "p",        "text": "附赠：本车辆过户登记手续的全部费用。"},
    {"kind": "table",    "rows": [["车辆总售价 TOTAL PRICE", "港币（大写）伍拾万元整（HK$500,000）"]]},
    {"kind": "p",        "text": "剩余购车尾款港币肆拾万元整（HK$400,000），须于…"},
    {"kind": "sign",     "rows": [["甲方（卖方）…签署／授权代表签署：…", "乙方（买方）…签署／授权代表签署：…"]], "stamped": true}
  ],
  "content_available": true,
  "content": {
    "form": { "client_name": "陈大文", "client_id": "H123456(7)", "plate": "LN 1234",
               "vin": "...", "model": "Toyota Alphard", "year": "2024",
               "total_price": 500000, "currency": "HKD", "sign_date": "2026-11-18", "...": "..." },
    "payment": { "mode": "default", "deposit_amount": 100000,
                  "deposit_date": "2026-11-18", "balance_date": "2026-12-18", "choice": "较早者" }
  }
}
```

**blocks 规则**：

- 块的顺序与 docx 合同**完全一致**，固定文本原样在块里，照抄渲染即可
- 动态条款（附赠/质保/无事故保证/其他承诺等）在服务端组装时就已定稿：勾了的以块的形式出现，没勾的**整块不存在**——前端不需要知道任何「勾选→段落」规则
- `sign` 块恒为最后一个块，带 `stamped` 字段：合同生成时公司侧（甲方或乙方，随业务）已预盖公司签字+公章（docx 内嵌图），小程序渲染公司侧时叠加印章图（接口 6/7）即可；`rows` 里含签署栏下划线占位（`____`），客户签名图（接口 5）叠加在客户格
- 表格 `rows` 是二维字符串数组；模板里的合并单元格以空串占位，前端按普通表格渲染即可
- blocks 对**所有**已生成合同可用（包括早期只有文件、没有 form.json 存档的单）

**content（form/payment）只是补充数据**——前端自己页面想显示客户名、车牌、金额做摘要卡片时用。`form` 字段按 `type` 不同而不同，字段表见下文。`content_available=false` 表示该单生成于存档机制上线前，`content` 为空，但 `blocks` 照常可用，渲染不受影响。

### 3. 下载 docx 原件

```
GET /api/open/contracts/{no}/file
```

合同生成时公司侧已内嵌公司签字+公章图；已签署的单返回**已签版**（另含客户手写签名图），未签返回原版（已带公司印信）。

### 3b. 公司印信图

```
GET /api/open/company-seal.png   # 公司公章（透明 PNG）
GET /api/open/company-sign.png   # 公司签字（透明 PNG）
```

小程序渲染 `sign` 块公司侧时叠加用（公司侧在甲方还是乙方随业务不同，`sign` 块 `stamped=true` 表示该单已含印信）。

### 4. 提交手写签名

```
POST /api/open/contracts/{no}/signature
Content-Type: application/json

{"image": "data:image/png;base64,...."}
```

- 签名图要求：**PNG 透明底**、宽度建议 ≥600px、横条比例（签名文字条），≤2MB
- 服务端把签名合成进合同客户签署格（客户在甲方还是乙方随业务不同），存为「已签版」副本（原 docx 不覆盖），状态变更为已签
- 重复提交返回 409（已签的单不可重复签）
- 返回 `{"ok": true, "no": "...", "signed_filename": "...-已签.docx"}`

### 5. 获取签名图（已签合同）

```
GET /api/open/contracts/{no}/signature
```

返回签名 PNG（透明底）二进制。未签署返回 404。小程序在已签合同的 `sign` 块客户格（不含「华星」的一侧，客户在甲方还是乙方随业务不同）叠加显示这张图即可，无需下载 docx。

## 字段表（form 各业务字段）

**car（卖车）**：`agreement_no, sign_date, currency(HKD/CNY), client_name, client_id, client_contact, client_phone, client_address, plate, vin, model, year, total_price` + 可选勾选项 `gift_transfer, gift_plate, gift_insurance, gift_other, accident_free, warranty_enabled, warranty_period, warranty_km, promise_other`

**car_buy（收车）**：`agreement_no, sign_date, currency(HKD/CNY), client_name, client_id, client_phone, client_address, seller_rep, plate, vin, mileage, reg_number, delivery_date, transfer_deadline, actual_delivery, reg_keep, total_price`。客户是**卖方（甲方）**、华星是买方（乙方）；无费用表与勾选项——购买总价/首期款/余款是正文散文条款（金额对外换算不加 1.01 加成），签署块在 `sign` 块甲方列（仍以不含「华星」一侧为准）。

**transfer_gx / transfer_ns（过户）**：`agreement_no, sign_date, currency, client_name, client_id, client_phone, plate, port, quota_type, target_hk_company, target_ml_company(仅纳税), total_fee, exchange_fee, gift_items`

**new_port（新办）**：`agreement_no, sign_date, currency, port(莲塘/深圳湾/港珠澳/沙头角口岸), client_name, client_id, client_phone, total_fee, gift_items`

**immigration（高才移民）**：`agreement_no, sign_date, currency, client_name, client_id, client_contact, client_phone, client_address, total_fee, lead_applicant, spouse_name, minor_children, total_applicants`

**payment（付款，所有业务同构）**：`mode(default=订金+尾款 / one_time=一次性 / custom=自定义分期 / car_buy=收车固定两期)`, `deposit_amount, deposit_date, balance_date, pay_date, installments[{seq, amount, label, trigger, trigger_date}]`。分期条款的成文（含双币大写金额）以 `blocks` 里的正文/表格为准，这里只作摘要数据。car_buy 恒为两期（首期款/余款，合计=购买总价），`trigger` 是模板固定文案、`trigger_date` 为空——时点不参与落盘，无自定义分期。

## 小程序渲染样式规范（按 blocks 的 kind 对应，实测值换算）

按 `blocks` 顺序竖版滚动长页渲染，每种 kind 对应样式如下：

| kind | 内容 | 字号（pt → 建议小程序 px） | 颜色 | 其他 |
|---|---|---|---|---|
| `title` | 主标题（如「车辆买卖合约（香港）」） | 22pt → 29px | #17324D 深蓝 | 加粗、居中 |
| `subtitle` | 英文副标（MOTOR VEHICLE SALES...） | 10pt → 13px | #B58A3A 金 | 加粗、居中、全大写 |
| `meta` | 编号/签署日期行 | 7.5pt → 10px | #6F7E8C 灰蓝 | 加粗 |
| `h` | 条款标题（`text`=中文如「一、合约双方」，`en`=英文小标如 PARTIES） | 中文 14pt → 19px / 英文 9pt → 12px | 中文黑、英文 #B58A3A | 同一行：中文序号+标题，空两格接英文小标 |
| `p` | 条款正文 | 10pt → 13px | 黑 #1D2733 | 行距 1.6 |
| `table` | 数据表（双方信息/车辆数据/费用/分期） | 10pt → 13px | 表头白字深蓝底 #0B2E59 | 有边框 |
| `sign` | 签署块（恒为最后一块） | 与正文同 | — | 双方两列：公司侧叠加章图+签字图（接口 3b，`stamped=true` 的单公司侧已含印信）、客户侧已签的叠加签名图（接口 5）；公司侧在甲方还是乙方随业务不同，以 `rows` 文本含「华星」一侧为准 |

全局字体：**中文微软雅黑（fallback：思源黑体/PingFang SC）、西文微软雅黑**。

说明：部分早期合同的条款标题在原文档里就是正文样式，服务端已按形态归一成 `h` 块，前端无需处理差异。

## 签名交互建议

1. 确认页底部放「签名并提交」按钮 → 全屏签名画板（横条画布，比例约 5:2）
2. 笔迹黑色、透明背景、导出 PNG
3. 提交后把 `signed` 置为已签状态；展示已签版时用接口 5 取签名图叠进 `sign` 块

## 部署注意

- 服务端 `.env` / 环境变量增加 `OPEN_API_KEY=<随机长串>`；**不配置则对外接口整体关闭**
- 接口只读（签名回传除外），不暴露服务器内部路径；docx 文件名由服务端生成，不接受外部路径参数
