I.

现状三个真问题

DIAGNOSIS
FORM-FIRST REVERSAL
「填表」被当成了主舞台
进站默认展开 3 张「档案卡」+ 5~10 个 input + 1 张付款表。粘文字只是一行窄 textarea + 一个按钮。视觉重量和实际使用频率完全反过来。
SIGNAL LOSS
「还差 X 项」离字段太远
底部一个 pill 写着"未完成 5 项"，要人眼对照 5 个 input 找。AI 填了什么、改了什么、漏了什么——三个状态用同一种颜色高亮，分不清。
CONTEXT ORPHAN
历史和当前合同互相看不见
历史抽屉是孤岛，跟当前正在编的合同毫无关联。同一个客户上周签的合同、续约记录，没有任何提示。生成按钮也藏在付款表后面。

推荐组合

首推 B（合同草稿视图）——最贴合「合同生成系统」这个产品语义。用户面对的不是表单而是合同本身，AI 抽取的成果直接在文档里高亮呈现，最自然。改造量虽大但收益也最显著。

备选 C（Notion 流式）——如果不想动现有视觉语言、走最稳路线，扫一眼就能上手。

A 不建议作主方案——对话单独撑不起结构化录入，会失去表单的速度优势。

D 作为新视觉上线前的过渡——保留为"主题二"，给老用户回退路径。
