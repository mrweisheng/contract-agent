# 引擎调用说明（快速制单通道）

常规单据**不要手写排版脚本**，直接把业务资料整理成下面的 JSON，一条命令出 PDF：

```bash
bash <skill包>/scripts/settle.sh --input - --png --clipboard --brief <<'JSON'
{...业务 JSON...}
JSON
```

（等价写法：`<skill包>/.venv/bin/python <skill包>/scripts/make_settlement.py …`）

- **推荐 stdin 直传**（`--input -`），省掉写文件这一步；`--png` 出 220DPI 图，`--clipboard` 自动把图放进系统剪贴板（用户 ⌘V 直接发微信），`--brief` 只打一行摘要。全流程实测 **0.6 秒**。
- **交付物：PNG + PDF 同时给**（PNG 优先）。PDF 是用户要改的源文件，图片是发给客户的成品，不能只给其中一个，更不能等确认后再补图。
- 脚本退出码 2 = 版式溢出（warnings 里有说明）；0 = 正常；1 = 核算冲突（先追问再生成）。
- 依赖只有两个：**reportlab**（排 PDF）+ **pypdfium2**（出 PNG）。首次安装跑 `bash <skill包>/install.sh`，它会建包内 `.venv` 并装好，之后不要反复 pip install。
- 出 PNG 统一用 pypdfium2（220 DPI），**不要改用 pdftoppm / magick / 在线转换**——换工具会改变像素和字体渲染，跟定稿版式对不上。
- 换机器后先跑 `python scripts/check_env.py --sample` 自检：字体、依赖、资源、样板出单一次验完。

## 币种与汇率字段要点

- `contract_unpaid` 里的人民币款项：**直接写 `currency: "CNY"`，不要塞 `hkd_equiv` 去把它挪进港币区**——明细只按人民币列示一次，港币等值由 `note` 和汇总口径体现。
- `contract_paid` 写**客户实付金额**（如实付 `$58,400`）；合同等值差额在 `note` 里说明。
- `rate`：`apply_101` **默认 `true`，人民币折港币一律 ×1.01（铁律）**，不要因为用了双币等值比率就关掉；只有用户直接给出最终港币应收金额、或当次明确说不用乘时才填 `false`。填法示例：`{"cny_to_hkd": 1.16938, "apply_101": true, "basis": "contract", "date": "…"}`。
- `today_sep`：可选。填 `"/"` 时「您今日需付」两个金额中间画出斜杠分隔（用户淇淇 2026-10-01 起偏好此样式，双币收款单默认带上）。注意：compute 的 spec 是白名单制，新增自定义选项必须在 `settlement_compute.py` 里显式透传，否则会被静默丢弃。
- `note`：自定义备注。**2026-10-01 起不再单独占一个框**，而是与 `amount_note` 合并成横幅下方的一行「備註：」——正文浅灰、首行从标签后起、续行悬挂对齐到「備」字下方，引擎按实际字宽自动折行并按行数算高度。写长的双币等值句不会压到账户区。
- `amount_note`：不填则按币种结构自动生成（负数说明／跨币种说明）。它和 `note` 会按「amount_note 在前、note 在后」顺序拼成同一段備註，中间以空格连接；两段都要保留时直接都填。
- 涉及两种币种时，汇总区自动并列「折合人民币 + 折合港币」两个口径。

## 业务 JSON（--input）

```json
{
  "customer": "卓康河",              // 客户名（脚本自动转香港繁体）
  "group": "0415卓康河莲塘新办Z3U86港", // 群名，保持简体，不转繁体
  "port": "莲塘口岸",                // 或 "vehicle": "日产 WY5469"（车辆买卖）
  "settle_type": "收尾款",           // 收尾款/收第二期款/杂费/补款/阶段款/其他（决定本次收哪几笔）
  "date": "2026年9月24日",           // 单据显示日期
  "date_iso": "20260924",           // 用于文件名，可省略（从 date 提取）
  "title": "收款結算單",             // 车辆买卖用 "港車買賣結算單"
  "contract_total":   [{"item": "车牌总价", "amount": 180000, "currency": "CNY"}],
  "contract_paid":    [{"item": "定金", "amount": 50000, "currency": "HKD"}],
  "contract_unpaid":  [{"item": "车牌尾款", "amount": 20000, "currency": "CNY",
                        "hkd_equiv": 23587.54}],   // 人民币款按港币等值收取时
  "extra_fees":       [{"item": "批文卡", "amount": 260, "currency": "HKD"}],
  "extra_paid":       [{"item": "验车垫付", "amount": 5000, "currency": "HKD"}],
  "rate": {"cny_to_hkd": 1.1794, "date": "2026-09-24", "source": "百度",
           "basis": "contract", "apply_101": true},
  "note": null,                      // 不填则自动生成；双币等值自动写入备注
  "amount_note": null                // 不填则自动生成
}
```

字段规则：

- 金额正数=应收，`contract_paid`/`extra_paid` 自动取负并标红。
- 项目名、口岸、结算类型用简体或繁体都行，脚本统一转香港繁体；群名保持原样。
- `contract_unpaid` 带 `hkd_equiv`：该行仍**只在人民币区列示一次**，`hkd_equiv` 只用于备注和「您今日需付」的港币口径；用户已给出等值金额时直接采用该等值，不再用汇率重复折算。
- `contract_unpaid` 每笔的 `status`：`today`（本次应收，默认）／`next`（下次收款，浅灰蓝字、**不计入今日需付**）／`paid`（已收）。
- **结算类型决定本次收哪几笔**：`settle_type` 含「第二期」时，只有名称含「第二期」的未收行计入今日需付，其余（如车牌尾款）自动降为 `next`；含「尾款」时只有名称含「尾款」的行计入。引擎自动判定并在 warnings 里说明，不要手动指定 `status` 去绕过它；判断不了就先问用户。
- `contract_unpaid` 不填时，本次应收 = 合同总价 − 已收 + 杂费余额；填了则以未收为准，不做二次相减。
- 双币均需收款时必须给 `rate`，脚本按合同口径折算并自动乘 1.01（`apply_101: false` 可关）；没有汇率时脚本会报 warning，此时先追问，不要瞎填。
- 展示金额自动截尾补 `.00`（不四舍五入）；分位栏自动去前导 0。
- 单币种自动省略备注区；只有“您今日需付”一个口径。

## 引擎已固化的规则（不要再心算、不要再写脚本）

尾款对账、合同内/外分开核算、双向汇率互为倒数校验、×1.01 收款系数、截尾显示、
分位栏前导 0、金额分位列、简繁转换（群名与大陆账户除外）、浅黄“您今日需付”框、
已收红字、账户区固定文字、溢出自动压行高并在放不下时报错，
以及 2026-10-01 定稿的三档线色／Logo 位置／序号字号统一／備註行合并与悬挂缩进（见 SKILL.md「视觉定稿参数」）。
**这些都不需要每次交代，也不要因为“想统一风格”而自行改动。**

仅当版式确实需要特殊调整时，在 spec 里加：

```json
"overrides": {"row_height": 20}
```

## 录入看板已直连引擎

`templates/录入看板.html` 生成业务资料时会同时产出**人读文本**和**引擎 JSON**两个标签页：

- 如果用户直接把「引擎 JSON」整段粘过来，**不要重新解析成自己的结构**，直接存成 `business.json` 执行 make_settlement.py。
- 如果用户贴的是人读文本，用 `--text` 模式，或自己转成上面的业务 JSON，不要再手写脚本。
- 看板 JSON 已含 group / customer / settle_type / date / date_iso / port 或 vehicle / 各段落明细 / hkd_equiv；模型只需检查有没有明显缺项，不必重算。

## 也可以直接喂标准段落文本（--text）

按 `input-format.md` 的段落格式写进 txt，`--text note.txt` 会自动解析：
支持 `18万`、`¥18000/$21060`、`18000，21060`、段落内币种继承、“政府收费”等分组标题自动忽略。
