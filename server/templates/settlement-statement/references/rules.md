# 结算规则

## 统一版式基准

- `assets/收款结算单统一版式基准.pdf` 是全部收款结算单的固定视觉母版，当前版本即用户最终逐项调整后的样式。后续两地牌、新办、现牌、车辆买卖单币版和车辆买卖双币版都使用同一套视觉规范。
- 原有 `两地牌结算单模板.pdf`、`港车买卖结算单模板.pdf`、`港车买卖结算单双币版模板.pdf` 仅用于识别不同业务应出现的项目、字段和币种区，不再作为颜色、字号、间距或账户区排版的依据。
- 车辆买卖结算单必须同样使用：左上固定 Logo、累计放大四号的字号、深蓝表头、人民币浅蓝底、港币浅绿底、已付款红字、下次收款浅灰蓝字、浅黄色“您今日需付”框、金额说明与账户表之间两行留白，以及当前账户资料布局。
- 仅港币车辆买卖单可以省略人民币币种区；双币车辆买卖单按人民币区在前、港币区在后的顺序显示。省略或增加币种区时，不得改变其他版式规则。
- 车辆买卖的项目名称按真实业务替换，例如车价、定金、车辆尾款、过户、保险、牌费、验车、运输、维修或代办费；不得套用两地牌的车牌总价、批文卡、禁区纸或核证本，除非用户本次明确提供。
- 车辆买卖业务中，如果客户尚未支付任何合同款，车辆总价本身即代表合同内本次应收，明细只列“车辆总价”，不得再重复列一笔同额的“车辆尾款”或“车辆尾款（今日应收）”。只有已经存在定金、前期款等已付款项，需要展示扣减后的余额时，才另列车辆尾款。
- 车辆买卖业务选择“总价一次性支付”且状态为已收时，合同总价只显示一次：直接将“车辆总价”标记为已收，整行使用红色并以负数列示。不得再新增一条同额的“总价一次性支付”、已付款项或车辆尾款；“您今日需付”也不得再次计入该车辆总价，只计算尚未支付的合同外杂费或其他应收。
- 后续如果用户没有明确要求修改模板，直接使用统一版式基准，不再逐次重新选择风格或询问配色。

## 生成速度与数据边界

- 本结算单流程不接入飞书多维表格，不负责飞书提醒、到账追踪、催款或飞书数据同步；这些工作由用户自行处理。
- 结算单只依赖当前用户提供的业务资料、固定模板和本地生成引擎。不得为了制作单据主动读取或维护飞书数据。
- 常规完整资料采用快速制作模式：一次结构化、一次核算、一次排版，并连续输出 PDF 与 PNG；不得为同一张单据重复计算、重复加载模板或重复读取无关 Skill 内容。
- 本地客户历史档案必须保留，用于后续查找、复用、核对和追溯。档案只保存制作结算单所需字段：客户、群名、业务类型、合同金额、已收/未收明细、合同外杂费、结算状态、结算单文件名、版本状态和更新时间；不保存无关聊天内容。
- 每张结算单对应一条历史记录；修改后不得覆盖旧版本，应保留旧版本状态并将最新版本标记为当前版本。
- 本地档案不承担飞书提醒或到账催收功能，不自动发送外部消息。
- 快速模式目标为常规单据 10–30 秒完成。遇到金额冲突、缺少汇率、币种不明、项目无法归类或版式溢出时，必须暂停并指出具体问题，不以提速为理由猜测。

## 数据优先级

1. 当前用户明确提供的数字和更正
2. 当前业务合同截图中的数字与币种
3. 用户提供的其他费用明细
4. 固定收费规则
5. 历史结算单仅作版式和项目名称参考，不覆盖当前合同

## 两地牌新办固定项目

人民币区通常固定列示：

- 车牌总价
- 定金（已付款，负数）
- 第二期款（已付款，负数）
- 本次应收尾款

港币政府收费固定为：

- 批文卡：HKD 260.00
- 禁区纸：HKD 744.00
- 核证本：HKD 300.00
- 三项合计：HKD 1,304.00

只有用户明确说明收费有变化时才覆盖固定金额。

## 合同外杂费看板默认项

- 两地牌结算单看板默认提供：批文卡 HKD 260、禁区纸 HKD 744、核证本 HKD 300。
- 新办结算单看板默认提供：批文卡 HKD 260、禁区纸 HKD 744、核证本 HKD 300。
- 现牌结算单看板默认提供：换车费 RMB 5,000、批文卡 HKD 260、禁区纸 HKD 744、核证本 HKD 300。
- 购车结算单看板不带入两地牌政府收费，默认提供：过户 HKD 1,500、保险 HKD（金额待填）、牌费 HKD（金额待填）。
- 所有自动带入的费用都不是不可修改的固定值。用户可以修改金额、修改项目名称、删除或新增项目，最终以本次录入内容为准。
- 车辆买卖可添加保险、牌费、过户、验车、运输、维修、代办等项目，不得套用两地牌政府收费。

## 核算

- 尾款校验：车牌总价 - 定金 - 第二期款 = 尾款。
- 若合同另有阶段款、优惠、退款或补款，逐项列示并保留正负号。
- 合同内费用和合同外杂费分开核算；合同外杂费实收按相同币种从合同外应收中扣减。
- 合同外杂费实收的项目名称由用户在录入看板手动填写，结算单的红色负数扣减行必须使用该名称，不得固定写成“合同外杂费已收”。用户未填写名称时才回退使用通用名称“合同外杂费已收”。
- 本次应收总额应只包含本次需要收取的款项，不把合同总价或已付款再次计入。
- 本次收款范围由「结算类型」决定，不得把所有未收款项一并计入：结算类型为「收第二期款」时，本次只收第二期款，其余未收款（如车牌尾款）只是应收事实，必须按「下次收款」列示，用浅灰蓝色字体、不计入今日需付；结算类型为「收尾款」时，本次只收尾款。只有结算类型本身同时涵盖多项（例如「收第二期款及尾款」）或用户明确要求本次一并收取时，才把多笔并入今日需付。
- 无法从结算类型判断本次收款范围、或用户给的未收款状态与结算类型互相矛盾时，先向用户确认本次究竟收哪几笔，不得自行合并收取。
- 用户已直接给出某笔款项的目标币种等值金额（例如第二期款 `¥150,000，$175,407`）时，该币种的付款口径直接采用用户给出的等值金额，不再用汇率重复折算；另一币种口径同理。
- 涉及多币种时，先分别计算每一种货币的剩余应收，不得在这一步跨币种相加。
- 再用同一时点、互为倒数的一组汇率，给出两个汇算结果：全部折合人民币的总应收，以及全部折合港币的总应收。
- 原币种余额用于内部核算和明细行检查，但结算单汇总区不再单列“原币应收”。汇总区仅显示“您今日需付：”，并列示全部折合人民币和全部折合港币的两个付款口径。
- “您今日需付”汇总区的港币金额只使用 `$` 符号，不加 `HK`，例如 `$ 13,020.46`。币种含义由左右并列的人民币/港币付款口径和汇率说明确定。
- 合同内已收项目名称只写“定金”“第二期款”，不加“合同内”前缀。
- 合同内未收的车牌尾款只在人民币区列示一次，项目名使用“车牌未收尾款”。港币等值金额不得作为第二条收款项目重复列示，只能在“您今日需付”的港币总合计中使用。
- 同一笔款项不能同时出现在人民币明细和港币明细中；跨币种金额仅作为汇算依据，不作为重复收款项目。
- 如果用户明确给出同一款项的人民币金额和港币等值，收款明细仍只按人民币列示一次，但备注必须同时写明该款项的人民币和港币金额。例如：`车牌未收尾款为 ¥18,000.00／$21,060.00。`
- 备注区一般只用于说明人民币与港币之间的等额折算，包括双币等值金额、折算汇率及其口径。发生合同业务款跨币种折算时，加入：`汇率核算以合同签订日为标准。`，不得改成操作日或结算日汇率。
- 合同外杂费的合计、实收、未收及其如何组成今日应收，不在备注区重复说明；这些信息只在明细行和“您今日需付”汇总中体现。合同外杂费实收为 0 时尤其不得在备注中写出“实收为 0”。
- 单据全部款项为同一币种、无需人民币与港币等额折算时，省略备注区，不为填充版面而增加合同外杂费说明或应收组成说明。

## 金额分位显示

- 金额分位栏按 `十万、万、千、百、十、元、角、分` 填写。
- 从左侧起省略元及以上的无意义前导 0。例如 `10,000.00` 的十万位留空，从万位开始填写 `1 0 0 0 0 0 0`。
- 金额中间与末尾的有效 0 必须保留；角、分固定保留两位。
- `260.00` 应从百位开始显示 `2 6 0 0 0`，十万、万、千位留空。

## 币种区显示与配色

- 同一币种区内，除已付款红字和下次收款浅灰蓝字外，所有普通、应收及今日应收项目统一使用深蓝色字体；不得再用绿色等其他字体颜色区分合同款与合同外杂费。币种区标题也统一使用深蓝色字体。

- 结算单全部文字统一采用相对初版累计放大四号的字号规范，包括标题、基本资料、收款明细、备注、汇总和收款账户资料；不得只放大局部文字。若放大后空间不足，应调整行高、换行或栏宽，不能将局部字体缩回原字号。
- “您今日需付”汇总框固定使用浅黄色背景和深蓝色文字。
- “金额说明：”字号比结算单统一字号规范小一号，并保留全角冒号。账户资料表与金额说明之间预留约两行文字高度的空白。
- 人民币明细行统一使用同一种浅蓝色背景，港币明细行统一使用同一种浅绿色背景；不得按已收、今日应收、下次收款等状态改成多种底色。
- 已付款项无论是定金、分期款或其他款项，整行文字均使用红色标记，底色仍保持所属币种的统一浅色背景。
- 状态为“下次收款”的项目，明细项目名只写款项名称，不在名称后添加“（下次收款）”字样；该行序号、名称、金额和金额分位统一使用较浅的灰蓝色字体。可在备注中说明其为下次收款且不计入今日应收。
- 只有某币种存在实际、非零的收款明细时，才显示该币种的明细区域。不得为“无费用”或金额为零的占位项目显示 `$0.00`、`¥0.00` 或空币种表格。
- 某笔人民币合同款的港币等值只用于备注或“您今日需付”汇总时，不因此额外创建港币明细区域；同一笔款项仍只在原收款币种明细中列示一次。

## 简繁体

- “群名”字段的内容使用简体中文；栏目标签“群名”本身不受影响。
- “大陆收款账户”整块使用简体中文，包括区块标题、开户银行、收款账号、网点号、名称、地址、电话及其中文内容。
- 除上述两处外，结算单其余所有中文统一使用香港繁体字，包括标题、客户名称、申请口岸、结算类型、收款项目、币种、备注、汇总说明和香港收款账户资料。
- 英文、数字、币种符号、账号和转数快识别码保持原文，不作繁简转换。

## 固定标识与大陆账户文字

- Logo 固定放在页面左上方，并较旧版位置略向左、向上靠近页边距，不与标题或正文重叠。
- 大陆账户的开户网点名称固定写作：`汕尾海丰东门头支行`。
- 大陆账户地址固定写作：`海丰县城人民中路7号`。
- 上述两处“海丰”均使用简体字，不得写成香港繁体“海豐”。

## 汇率

- 合同有汇率、双币等值金额或明确折算条款：严格按合同签订日口径。
- “合同签订日或合同汇率”为选填项；用户已经提供合同款的人民币及港币等值金额时，不要求再次填写，留空不得阻止生成业务资料、PDF 或结算单。
- 合同无汇率且用户要求折算：先向用户索取合同签订日或合同汇率；不得默认改用操作日实时汇率。
- 用户明确提供某笔合同业务款的人民币金额和港币等值时，直接使用该组双币金额，不再另查该笔款项的实时汇率。
- 合同外杂费没有合同双币等值时，按制作结算单当日的百度实时汇率折算，并在结算单中记录日期、方向和取值。
- 查到汇率后记录：汇率方向、数值、日期和来源。
- 双向换算必须使用同一基准汇率的正向值和倒数，不得分别取两个来源或两个时点的报价。
- 人民币折算港币时，先按适用的合同汇率、用户已提供的双币等值比率或当日百度实时基准汇率计算港币基础金额，再统一乘以 `1.01`。公式：`港币应收 = 人民币金额 ×（1 CNY 对 HKD 基准汇率）× 1.01`。内部计算至少保留 6 位小数，最终金额四舍五入至 2 位小数。
- 面向客户展示和收款的所有金额均不收取小数金额：无论内部计算结果的小数部分是多少，展示金额统一截去小数部分并显示为 `.00`，不得四舍五入；内部精确值仍须保留用于核算和留痕。
- `1.01` 是人民币转港币的收款折算系数，不属于基准汇率本身；基准双向汇率仍须互为倒数。**×1.01 只做不说：单据备注只记录基准汇率、日期、来源，严禁出现「×1.01」「收款系數」等字样**（淇淇 2026-10-02 指定，客户不需要知道）。
- **铁律（淇淇 2026-10-02 再次强调，最高优先级）：凡是人民币折成港币，一律 ×1.01，绝不允许漏乘。** 不要以"用户提供的双币等值已含 ×1.01"为由跳过——除非用户在当次明确说"这次不用乘 1.01"，否则必须乘。
- **铁律（淇淇 2026-10-02 指定）：「您今日需付」金额一律截尾到元，小数固定显示 `.00`。** 计算时保留完整精度，展示时无论分位是多少（如 177,161.07）都截为 177,161.00；不四舍五入。明细行、备注中的金额不受此条影响。
- 若用户已经直接给出**最终港币应收金额**（即港币数本身就是让收的数），直接采用该金额，此时不再二次折算；除这种情况外，任何人民币→港币的换算都必须带 `×1.01`。
- 用户未要求折算：双币分别列示，不自行选汇率。

## 待补信息

对不影响核算的缺失字段可合理推断，例如从群名提取客户姓名称呼和口岸；对会改变金额或模板类型的缺失信息不得猜测。若合同与用户文字冲突，先标出冲突并以用户最新明确更正为准。

## 交付状态

- `PDF 待确认`：已经生成、检查并在 Codex 展示 PDF，但尚未收到用户对该版本的明确确认。此状态不得主动生成最终图片。
- `需要修改`：用户指出修改内容。修改后必须回到 `PDF 待确认`，重新展示最新版 PDF。
- `已确认`：用户在最新 PDF 预览之后，单独或明确回复确认、确定、没问题、OK、ok、可以、无误、通过、好的等同义词，且没有附带修改、疑问或保留条件。
- `图片已交付`：一旦进入“已确认”状态，不再追问，立即自动将最新版 PDF 转为高清 PNG，在 Codex 展示并提供文件。若之后再修改，旧图片作废，重新走 PDF 确认流程。
- 通过词只有在确认最新 PDF 的语境中才生效；业务资料、附件内容、规则说明或要求把“确认/OK/可以”等词写入 Skill 的消息，不属于对当前 PDF 的确认。

## 模板触发

- 用户说“模板”“固定格式”“开始新单”“给我填写模板”，或发来空白字段时，返回可复制的填写模板。
- 模板中的业务类型和尾款项目用可选项呈现，不要求用户自行删除 `or` 的另一项。
- 用户未提供任何业务数据时，不生成 PDF；先给模板。

## 看板交互

- 基本资料同时收集“群名”和可手动填写的“客户”。
- “合同内已收款”项目提供“总价一次性支付”选项。选择后金额和币种跟随合同总价，并在生成业务资料时把合同总价标记为“已一次性支付”，不再输出一条同额的已收明细；车辆买卖业务同时移除默认的车辆尾款行，避免重复计收。
- 合同外杂费实收同时提供“已收项目名称”和“实收金额”两个可编辑字段。生成业务资料时将名称与金额作为一笔已收扣减项目输出；制作结算单时使用用户填写的项目名称显示红色负数行。
- 结算类型选择“其他”时，必须显示自由输入框并采用用户填写的名称。
- 合同内未收款项支持新增多笔；每一笔均可选择“第二期款”、按业务切换的“车牌尾款／车辆尾款”，或选择“其他”并手动填写项目名称。
- 每笔未收款项的人民币金额和港币等值放在该笔自己的输入框中，用逗号分隔，例如 `¥18,000，$21,060`；生成业务资料时逐笔输出，结算核算时不得把同笔双币金额重复计收。
- 看板中合同内已收和合同内未收的金额输入框使用较短宽度；两部分都必须提供独立的“人民币、港币等值金额”输入栏，输入格式参照 `¥　　　　/　$　　　　`。合同内未收区域的列顺序固定为“项目、金额、币种、状态、人民币、港币等值金额”。生成业务资料时，若等值栏有内容，必须逐笔带出，不得只保留页面上的输入值。已收与未收模块下方不再重复显示说明句。
- 合同内未收每笔包含独立状态：已收、应收、减免、退款/扣减、今日应收、下次收款；“今日应收/下次收款”表示收款安排，不代表实际到账。核算实际余额时按合同金额与已收/扣减事实处理，不能把收款安排状态当作真实收款。
- 点击“生成业务资料”后，必须在按钮附近显示明确的“已生成业务资料”成功提示。
- 点击“复制业务资料”且复制成功后，必须在按钮附近显示明确的“已复制业务资料”成功提示。提示区域使用 `role="status"` 和 `aria-live="polite"`，不能只依赖按钮文字、颜色或输出区底部状态变化。
- 生成业务资料后由用户人工审核。只有勾选确认无误后，“制作结算单”按钮才可用；点击后把已审核资料发送到当前对话，进入 PDF 预览流程。
